# Claim category test run — 5 November 2026

## Scope and reproduction

Each C01–C23 image in `category-cards/` was uploaded to the real FastAPI upload endpoint, OCR was run, the claim was extracted, Tavily was queried, evidence was compared using live Gemini where available, and a report was retrieved. The runner is `backend/scripts/evaluate_categories.py`. It uses a separate temporary database and upload directory. All 23 cards are locally generated test images, not authentic posts. Each contains a test label and footer. OCR read that surrounding text; in the first run all 23 claims required the app's single claim-correction step before retrieval. Thus these API runs verify the corrected-claim path, not fully automatic extraction for all cards. No answer or provider response is embedded in the fixtures.

To reproduce a row, upload `category-cards/<ID>.png`, allow automatic analysis, correct the claim to the corresponding `claim` in `category-evaluation.json` if prompted, and inspect the report and its citations. Compare the exact named person, event, place, country, date, and publisher with that card's `reference` and `why` fields. “Unverified” below is the app's conservative insufficient-evidence result, not a claim that the statement is false. Publication timestamps supplied by search are not event dates.

The initial API run used live Tavily and Gemini (configured fallback Gemini model), with local OCR and a rule fallback whenever Gemini failed or produced unusable output. The later API reruns also used live providers. Provider errors included HTTP server errors and invalid model output; the default Gemini model timed out during preflight, so the configured fallback model was used. Individual outcomes can vary with provider responses. The final C05 result was observed in the actual browser after the last fix, not in a final API rerun.

The real Vite/FastAPI browser flow was exercised with C05: welcome → upload → processing → refresh during processing → report → History → reopen → rerun. The final report was viewed at 390 px and 1280 px in বাংলা and English. No horizontal scrolling was observed (375 px document within 390 px viewport; 1265 within 1280). The official Paris citation was visible on the first screen; the evidence section expanded. After the publication-date label fix, the saved report was reopened through the production build served by FastAPI, and the search-listed date was visibly marked unverified. These browser checks were not repeated for all 23 cards. The API path was repeated for all 23.

Fixture-based regression tests cover source identity mismatches, India/Bangladesh, official address and inscription passages, indirect quotes, year and country guards, retry behavior, provider failure, publisher separation, and frontend report text. Fixture tests do not establish live search accuracy. The complete backend suite passed **106 tests** with one dependency deprecation warning. The complete frontend suite passed **21 tests**. The production build passed; emitted JS was **289.17 kB** (**86.28 kB gzip**) and CSS **27.07 kB** (**7.59 kB gzip**). Search-supplied publication dates are now labeled unverified; event dates remain separate and cited.

## Remaining limits

Live Tavily results can omit the decisive sentence, identify a related event, or omit country/date context. Gemini intermittently returned server errors or invalid structured output; its configured primary model timed out during preflight. The fallback and guardrails preserved an unverified report, but many examples remain unresolved. Synthetic cards with test labels caused claim correction in every API case; real news images need a separate live-media evaluation. Publisher confirmation and image authenticity remain unknown unless direct evidence exists. No claim is made that all news categories are solved.
